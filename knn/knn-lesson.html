Section 01

The Core Intuition

You just moved to a new city and want to know if a neighborhood is safe. What do you do? You ask your nearest neighbors — people who live closest to you. You don't build a model; you just look around and take a vote.

That is exactly what KNN does. For every new data point, it:

The KNN Algorithm (Classification)
  1. Calculate the distance from the query point to every training point.
  2. Sort training points by distance → pick the K closest ones.
  3. Take a majority vote of their labels.
  4. Assign that label to the query point.
💡
Why "Lazy Learner"? Linear/Logistic regression learn weights during training. KNN does zero computation at training time — it just memorizes all data. All the work happens at prediction time. This is called instance-based or lazy learning.
📐
Why "Non-Parametric"? Linear Regression has parameters (w₀, w₁ … wₙ). Logistic Regression too. KNN has no parameters to learn — it doesn't compress the data into a formula. The number K is a hyperparameter, not a learned parameter.
Section 02

Mathematical Foundation

Formal Definition

Given a training set D = {(x⁽¹⁾, y⁽¹⁾), …, (x⁽ⁿ⁾, y⁽ⁿ⁾)} and a query point x:

-- Step 1: Compute distances from query x to all training points -- d(x, x⁽ⁱ⁾) = distance_function(x, x⁽ⁱ⁾) for i = 1 to n -- Step 2: Find the K Nearest Neighbors -- N_K(x) = { K training points with smallest d(x, x⁽ⁱ⁾) } -- Step 3 (Classification): Majority Vote -- ŷ = argmax_c Σ 𝟙[y⁽ⁱ⁾ = c] x⁽ⁱ⁾ ∈ N_K(x) -- 𝟙[condition] = 1 if condition is true, 0 otherwise -- -- argmax_c = class c that gets the most votes --
🔢
Reading the formula: We look at all K neighbors. For each possible class c, we count how many of those K neighbors belong to class c. We predict whichever class c gets the highest count. Simple democracy.

Decision Boundary

Unlike logistic regression that draws a single smooth line, KNN creates a Voronoi-like decision boundary — a complex, non-linear boundary that adapts to the local structure of your data.

K=1 Decision Rule
When K=1, prediction is simply: ŷ = y⁽ⁱ*⁾ where i* = argmin_i d(x, x⁽ⁱ⁾) → Assign the label of the single closest neighbor → Creates the most complex, jagged boundary → Zero training error (overfitting!)
Section 03

Distance Metrics — The Heart of KNN

The entire algorithm depends on your definition of "nearest." Different distance metrics reveal different structures in your data.

1. Euclidean Distance (L2 Norm)

Straight-line distance. Most common default choice.

d_Euclidean(x, z) = √( Σᵢ (xᵢ - zᵢ)² ) For 2D: d = √( (x₁-z₁)² + (x₂-z₂)² ) Example: x = [3, 4], z = [0, 0] d = √(3² + 4²) = √(9+16) = √25 = 5

2. Manhattan Distance (L1 Norm)

Sum of absolute differences. Imagine walking on a grid — you can only go N/S/E/W, not diagonally.

d_Manhattan(x, z) = Σᵢ |xᵢ - zᵢ| For 2D: d = |x₁-z₁| + |x₂-z₂| Example: x = [3, 4], z = [0, 0] d = |3-0| + |4-0| = 3 + 4 = 7

3. Minkowski Distance (Generalization)

Euclidean and Manhattan are special cases of this general form:

d_Minkowski(x, z, p) = ( Σᵢ |xᵢ - zᵢ|ᵖ )^(1/p) p = 1 → Manhattan Distance p = 2 → Euclidean Distance p → ∞ → Chebyshev Distance (max of absolute diffs)

4. Cosine Similarity (for text/embeddings)

Measures the angle between two vectors, not their magnitude. Used when you care about direction, not length (text documents, word embeddings).

cos_sim(x, z) = (x · z) / (‖x‖ · ‖z‖) = Σᵢ(xᵢzᵢ) / √(Σxᵢ²) · √(Σzᵢ²) Range: [-1, 1] → Cosine Distance = 1 - cos_sim

5. Hamming Distance (for categorical)

d_Hamming = (number of positions where the two strings differ) / total_length Example: "karrot" vs "carrot" → Position 0: k≠c (different) → Positions 1-5: same d = 1/6 = 0.167
⚠️ Feature Scaling is CRITICAL for KNN

Imagine features: Age (0–80), Salary (0–200,000). Euclidean distance will be dominated by Salary. A difference of $1000 vs a 10-year age difference — salary wins every time. Always StandardScale or MinMaxScale before KNN.

StandardScaler (Z-score normalization): x_scaled = (x - μ) / σ MinMaxScaler: x_scaled = (x - x_min) / (x_max - x_min) → maps to [0, 1]

Section 05

Choosing K — Bias vs Variance Trade-off

Small K (e.g. K=1): High Variance, Low Bias → Captures every local fluctuation → Overfits → Decision boundary is very jagged → Training error = 0 (always picks itself) Large K (e.g. K=N): Low Variance, High Bias → Predicts the majority class for everything → Underfits → Decision boundary becomes nearly linear → Ignores all local structure Optimal K: → Found by cross-validation (usually odd K to avoid ties) → Typical starting point: K = √N

The Error Curve

As K increases from 1 → N: Training Error: ↗ increases (less memorization) Test Error: ↘ decreases first (reducing overfitting) ↗ then increases (underfitting kicks in) Sweet spot: where test error is minimum → Use k-fold cross-validation to find it
🎯
Rule of thumb: Start with K = √n where n is number of training samples. Use odd K for binary classification to avoid ties. Always validate with cross-validation.

Weighted KNN — Smarter Voting

Instead of equal votes, closer neighbors get more weight:

Standard KNN: each neighbor votes with weight = 1 Weighted KNN: neighbor i votes with weight: w⁽ⁱ⁾ = 1 / d(x, x⁽ⁱ⁾)² ← inverse square distance Prediction: ŷ = argmax_c Σ w⁽ⁱ⁾ · 𝟙[y⁽ⁱ⁾ = c] x⁽ⁱ⁾ ∈ N_K(x) → Avoids tie-breaking issues → More robust to noisy neighbors at the boundary
Section 06

KNN for Regression

Instead of voting, we average the values of the K nearest neighbors:

KNN Regression: ŷ = (1/K) · Σ y⁽ⁱ⁾ x⁽ⁱ⁾ ∈ N_K(x) → Simple average of K neighbors' target values Weighted KNN Regression: ŷ = ( Σ w⁽ⁱ⁾ · y⁽ⁱ⁾ ) / ( Σ w⁽ⁱ⁾ ) where w⁽ⁱ⁾ = 1 / d(x, x⁽ⁱ⁾) (inverse distance weighting)
📈
Example — Predicting House Price: Query = 3-bed house in neighborhood X. KNN finds 5 nearest houses (by features: beds, area, location). Predicts price = average of those 5 houses' prices. No formula, no coefficients — just local averaging.
Section 07

Time & Space Complexity

Training Time: O(1) ← just store the data Prediction Time (brute force): → Compute n distances: O(n · d) n = samples, d = features → Sort distances: O(n · log n) → Total per query: O(n · d) Space Complexity: O(n · d) ← store all training data For m test queries, total prediction cost: O(m · n · d)
The Curse of Dimensionality

As dimensions (features) increase, distances between all points converge — everything becomes equally "far" from everything else. With 1000 features, your "nearest" neighbor might be almost as far as your "furthest" neighbor. KNN breaks down in high-dimensional spaces.

In high-D space: d_max / d_min → 1 as d → ∞ → All points look equally distant → "Nearest" is no longer meaningful → Solution: PCA / dimensionality reduction before KNN

KD-Trees — Faster Neighbor Search

For low-dimensional data (d < 20), KD-Trees pre-partition the space to speed up search:

KD-Tree Build Time: O(n · log n) KD-Tree Query Time: O(log n) ← massive speedup! Ball Trees also work well for higher dimensions and non-Euclidean metrics → sklearn's KNeighborsClassifier uses auto-selection

Implementation from Scratch

import numpy as np from collections import Counter class KNNClassifier: def __init__(self, k=3, metric='euclidean'): self.k = k self.metric = metric def fit(self, X, y): # KNN has no training — just store the data self.X_train = X self.y_train = y def _distance(self, a, b): if self.metric == 'euclidean': return np.sqrt(np.sum((a - b) ** 2)) elif self.metric == 'manhattan': return np.sum(np.abs(a - b)) def _predict_one(self, x): # Compute distances to all training points distances = [self._distance(x, x_train) for x_train in self.X_train] # Sort and get K nearest indices k_indices = np.argsort(distances)[:self.k] # Get labels of K nearest neighbors k_labels = [self.y_train[i] for i in k_indices] # Majority vote most_common = Counter(k_labels).most_common(1) return most_common[0][0] def predict(self, X): return [self._predict_one(x) for x in X] # ── Usage ────────────────────────────────────── from sklearn.datasets import load_iris from sklearn.model_selection import train_test_split from sklearn.preprocessing import StandardScaler X, y = load_iris(return_X_y=True) # ⚠️ Always scale features before KNN scaler = StandardScaler() X_scaled = scaler.fit_transform(X) X_train, X_test, y_train, y_test = train_test_split( X_scaled, y, test_size=0.2, random_state=42 ) knn = KNNClassifier(k=5, metric='euclidean') knn.fit(X_train, y_train) preds = knn.predict(X_test) accuracy = np.mean(np.array(preds) == y_test) print(f"Accuracy: {accuracy:.2%}") # ~96.67%

Using sklearn

from sklearn.neighbors import KNeighborsClassifier from sklearn.model_selection import cross_val_score import matplotlib.pyplot as plt # Find best K via cross-validation k_range = range(1, 31) cv_scores = [] for k in k_range: knn = KNeighborsClassifier( n_neighbors=k, metric='euclidean', weights='distance' # weighted voting ) scores = cross_val_score(knn, X_train, y_train, cv=5) cv_scores.append(scores.mean()) best_k = k_range[np.argmax(cv_scores)] print(f"Best K: {best_k}")
Section 09

When to Use KNN

✅ Advantages

  • Simple, intuitive, easy to implement
  • No training time — add new data instantly
  • Non-linear decision boundaries
  • Naturally handles multi-class
  • No assumptions about data distribution

❌ Disadvantages

  • Slow prediction: O(n·d) per query
  • High memory: stores all training data
  • Sensitive to irrelevant features
  • Breaks down in high dimensions
  • Sensitive to scale → must normalize

Comparison with What You've Learned

Linear Regression

Fits one global line/plane. Works when data is truly linear. Extrapolates well. Fast at prediction.

Logistic Regression

Fits one global decision boundary (linear). Works well for linearly separable data. Gives probabilities.

KNN

No global model. Adapts locally. Handles complex shapes. But slow and memory-hungry at scale.

Recommended Use Cases for KNN
  • Small-to-medium datasets (< 100K samples)
  • Low-dimensional data (< 20 features after preprocessing)
  • Recommendation systems (user-user, item-item similarity)
  • Anomaly detection (outliers have large distances to all neighbors)
  • Image classification on small datasets (pixel-space KNN)
  • Baseline model before trying complex algorithms

Your ML Roadmap — Where KNN Fits

✓ Linear Regression → parametric, continuous output, global model ✓ Logistic Regression → parametric, classification, global model, gradient descent → KNN → non-parametric, lazy, local model, no gradient descent Decision Trees → non-parametric, tree structure, interpretable SVM → parametric, max-margin, kernel tricks Neural Networks → deep, hierarchical representations
